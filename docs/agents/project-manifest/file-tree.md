# File Tree

```
composer-local-switcher/
├── composer.json                — Package definition & autoload config
├── phpunit.xml                  — PHPUnit configuration
├── .phpunit.cache/              — PHPUnit result cache (gitignored)
├── changelog.md

│   ├── ConfigSwitcher.php       — Main orchestrator: `switchTo()`/`switchToDevelopment()`/`switchToProduction()`/`switchUpdate()` run through a single post-dispatch planner, `switch_plan()` (the v3 decision table — see `switching-decision-table.md`), which always runs `switch_cleanLegacyArtifacts()` first and then dispatches to exactly one of `switch_planProdToDev()`/`switch_planDevRefresh()`/`switch_planDevToProd()`/`switch_planProdToProd()`; each returns `{blocked, command, changes, snapshotHash, appliedRepositories}` and `ConfigSwitcher` itself never executes Composer or prompts the user. Every `composerSwitch*`/`composerSwitchPreview*` static entry point (`?object $event = null`) is a one-line delegation, via the private `buildRunner()` helper, to a `Utils\SwitchCommandRunner` — the only place that executes Composer or prompts (see `Utils/SwitchCommandRunner.php` below). The standalone `reconcile()`/`verify()` family and their `VerificationResult` return type were removed entirely once `composer-prod.json`/`.lock` became a transient DEV-session snapshot rather than a second committed baseline — there is no drift between two editable copies left to reconcile or verify
│   ├── ComposerSwitcherException.php — Exception class with error code constants
│   ├── State/
│   │   ├── SwitchMessage.php     — Immutable value object pairing a switch message's text with a `MESSAGE_*` code
│   │   ├── FileOperation.php     — Immutable value object describing a single file operation (copy/write/delete), performed or dry-run-planned
│   │   ├── SwitchOutcome.php     — Immutable value object summarizing a switch/preview result: target mode, dry-run flag, messages, file operations, the planned `ComposerCommand` (if any), `blocked` flag, and `ConfigChangeSet`; `hasSameEffectsAs()` is the "shown equals applied" comparison (ignores messages)
│   │   ├── SwitchDescription.php — Immutable snapshot of the switcher's current state, assembled by `ConfigSwitcher::describe()`

│   │   ├── ComposerCommand.php  — Immutable value object describing a planned Composer invocation: argument list (no binary) + reason; `toShellString()` escapes each argument independently
│   │   ├── DevTransformResult.php — Immutable result of `Utils\DevConfigTransformer::apply()`: the resulting DEV `composer.json` data plus a per-package version-derivation fact (`SOURCE_OVERRIDE`/`SOURCE_LOCKED`/`SOURCE_NONE`)
│   │   ├── RevertResult.php     — Immutable result of `Utils\DevConfigTransformer::revert()`: the three-way-merged effective config plus the list of managed entries the user edited anyway (discarded in favor of the snapshot value)
│   │   ├── ConfigChange.php     — Immutable record of a single structural difference (path/before/after/kind/origin), produced by `Utils\ConfigDiff::between()`; `isVersionChange()` flags a require/require-dev path or a repositories entry carrying `options.versions`
│   │   ├── ConfigChangeOrigin.php — Backed string enum (LocalSwitch|CarriedBack|Discarded): whose change a `ConfigChange` is, attached by the classifier `Utils\DevConfigTransformer::makeOriginClassifier()` builds
│   │   └── ConfigChangeSet.php  — Immutable set of `ConfigChange`s split into `composerJson`/`prodConfig` sections; `getProdChangedKeys()`/`getProdChangedPackages()` are derived from `prodConfig`
│   └── Utils/

│       ├── ComposerProcess.php  — Executes a planned ComposerCommand as a real child process via proc_open() (array form, inherited STDIN/STDOUT/STDERR); the only place in the library that spawns Composer; resolves the binary from an injected path, COMPOSER_BINARY, or an executable `composer` on PATH; sets COMPOSER_SWITCHER_NESTED=1 in the child's environment
│       ├── OutcomeRenderer.php  — Renders a SwitchOutcome/SwitchDescription as human-readable text through an injected EventContext; took over ConfigSwitcher's old printPreview()/formatOperation(); renders a ConfigChangeSet as a grouped list with [version]/[permanent]/[discarded] markers
│       ├── EventContext.php     — The sole duck-typing site for Composer's event/IO objects (getArguments()/getIO()/isInteractive()/askConfirmation()/write(), each probed once via method_exists()); not final, so a test double can extend it
│       ├── SwitchCommandRunner.php — The only place in the library that executes Composer or prompts the user; every composerSwitch*/composerSwitchPreview* static builds one and delegates; runs the full confirmation sequence (preview → render → confirm-or-skip → second preview via hasSameEffectsAs() → real switch → command execution), the nested-run guard, and --yes/--no-install/--with-dependencies/--no-interaction handling
│       ├── ComposerContentHash.php — Exact mirror of Composer 2.9.5's `Locker::getContentHash()`: `fromConfigData(array): string` extracts the relevant top-level keys plus `config.platform`, top-level `ksort()`, `md5(json_encode($x, 0))`
│       ├── ConfigDiff.php       — Structural diff between two composer.json-shaped arrays: `between()` recurses associative structures to leaf paths and compares `repositories` list entries item-by-item by value as whole Added/Removed changes; runs over the real before/after arrays a switch writes rather than a hand-maintained operation log
│       ├── DevConfigTransformer.php — Pure, static transform between a PROD-style `composer.json` and its DEV counterpart: `apply()` (replace/prune/append repository logic, PROD-lock-derived version aliasing), `revert()` (the three-way inverse, carrying back non-managed edits and restoring managed entries to their snapshot value), and `makeOriginClassifier()` (builds the callable `ConfigDiff::between()` consumes to attach `ConfigChangeOrigin`); replaces the former `ConfigSwitcher::switch_adjustConfigForDev()`/`urlMatchesPackageName()`, now ported in here
│       ├── InstalledPackages.php — Reads `<vendor-dir>/composer/installed.json` through FileSystem; `isInstalledFromPath()` tells whether a package is actually installed from a local path repository (vendor dir resolved from `config.vendor-dir`, default `vendor`); never throws (null = indeterminate, false = known-absent)

│       ├── ConsoleWriter.php    — Console output helper with header/line/separator methods
│       ├── FileSystem.php       — Single write choke-point for every file mutation (write/copy/delete); real I/O in normal mode, in-memory overlay + FileOperation log in dry-run mode; every real-mode native call (`file_get_contents()`/`file_put_contents()`/`unlink()`/`filemtime()`) is routed through a private `runNative()` helper that captures any native warning as an `\ErrorException` via a scoped `set_error_handler()`/`restore_error_handler()`, so no native warning ever escapes the facade — a real-mode failure's thrown `ComposerSwitcherException` carries that captured error under `KEY_NATIVE_ERROR` and chains it as `getPrevious()`
│       ├── FlagFile.php         — Creates mode indicator files (composer.json.DEV / .PROD)
│       ├── LockFile.php         — composer.lock file abstraction (derived from ConfigFile path) and reader: `getContentHash()`, `getLockStatus()` (derives `LockStatus` against its owning `ConfigFile` via `ComposerContentHash`), `getLockedVersion()` (searches `packages`/`packages-dev`) — all FileSystem-backed, never throw, never cache
```
